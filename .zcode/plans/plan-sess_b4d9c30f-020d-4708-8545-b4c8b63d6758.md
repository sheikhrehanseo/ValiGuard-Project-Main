## Stage 2 — Web3 auth: nonce → signature → JWT (greenfield)

Docs spec: Phase 1 Documentation §4.10 / UC-01 sequence (MetaMask signs nonce → backend verifies → JWT issued).

**Backend** — new `backend/auth/` package:
- `POST /api/v1/auth/request-nonce` — generates a random nonce bound to the wallet address, ~5-min TTL, in-memory store with cleanup.
- `POST /api/v1/auth/verify` — accepts address + signature; recovers signer via `eth_account` (EIP-191 `personal_sign`); on match, issues JWT (PyJWT, ~24h expiry) returning token + address.
- `GET /api/v1/auth/me` — returns the authenticated identity.
- `@require_auth` decorator (replaces the unused `require_api_key` as the default guard); apply to sensitive routes: `/bridge/history`, `/analytics/*`, `/bridge/alert`, validator endpoints. Health + auth routes stay open.
- Add `pyjwt` to `requirements.txt` (`web3`/`eth-account` already installed).

**Frontend** — extend `frontend/src/components/WalletConnect.js` and a shared API client:
- After MetaMask connect: request nonce → `signer.signMessage(nonce)` → POST verify → store JWT (localStorage + in-memory), attach `Authorization: Bearer` header to all fetches in `page.js`, handle 401 by re-running the auth flow.
- Keep the demo/fallback wallet working behind a `NEXT_PUBLIC_DEMO_MODE` flag so the dashboard is demoable without MetaMask.
